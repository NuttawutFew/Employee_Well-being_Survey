# ADR-0032: โครงสร้างบทบาทผู้ใช้งาน (3 Swimlanes) และการจัดการสิทธิ์ Admin (Admin Permission Management)

- สถานะ: ยอมรับแล้ว
- วันที่: 2026-09-08

## บริบท

ตามการปรับปรุงเส้นทางการใช้งานระบบ (User Journey ระบบตรวจสอบสุขภาพใจ ฉบับกันยายน 2569) มีการจำแนกบทบาทผู้ใช้งานออกเป็น 3 บทบาทหลักอย่างชัดเจน (3 Swimlanes) เพื่อเพิ่มความคล่องตัวในการดำเนินงานควบคู่กับมาตรการกำกับดูแลความมั่นคงปลอดภัยสารสนเทศ:
1. **พนักงาน (Employee)**: ผู้รับการประเมินสุขภาวะจิตใจ
2. **Super Admin**: ผู้ดูแลระบบระดับสูงสุดที่มีอำนาจกำหนดสิทธิ์และกำกับดูแลภาพรวม
3. **Admin (HR)**: ผู้ดูแลระบบฝ่ายทรัพยากรบุคคลที่ปฏิบัติงานดูแลสุขภาวะพนักงาน

เดิมระบบมีบทบาท Admin เพียงระดับเดียวและไม่ได้จำแนกสิทธิ์การส่งออกข้อมูล ทำให้เกิดความเสี่ยงในการเข้าถึงและการส่งออกข้อมูลสุขภาพของพนักงานเกินความจำเป็น จึงจำเป็นต้องมีโครงสร้างสิทธิ์ (Role Hierarchy), หน้าควบคุมส่วนกลาง (Super Admin Portal), และระบบจัดการสิทธิ์ผู้ดูแลระบบ (Admin Permission Management)

## การตัดสินใจ

1. **โครงสร้าง 3 บทบาทและการเข้าใช้งาน (3 Swimlanes)**:
   - **พนักงาน (Employee)**:
     - เข้าสู่ระบบผ่าน ONE ID ไปยังหน้า **Employee Portal (Step 2.1)**
     - เข้าสู่บริการด้วยปุ่ม **"เข้าทำแบบประเมิน" (Step 2.2)**
     - หน้าคำชี้แจงมีปุ่มกดเดี่ยว **"รับทราบ" (Step 3)** เพื่อเริ่มต้นทำแบบประเมิน
     - ดำเนินการทำแบบประเมิน 5 ชุด (74 ข้อ Autosave) จนถึงหน้าส่งผลและดูผลสรุปของฉัน (Step 6)
   - **Super Admin**:
     - เข้าสู่ระบบผ่าน ONE ID ไปยังหน้า **Super Admin Portal (Step 7)**
     - แสดง 2 การ์ดเมนูหลัก:
       1. **ระบบตรวจสอบสุขภาพใจ (Dashboard)** (Step 8) -> เพื่อดูรายงานภาพรวมและผลรายบุคคล
       2. **จัดการสิทธิ์ Admin (Admin Permission Management)** (Step 9) -> เพื่อบริหารจัดการสิทธิ์ผู้ดูแลระบบ
     - มีสิทธิ์เต็มในการบริหารจัดการ Admin และการส่งออกข้อมูล
   - **Admin (HR)**:
     - เข้าสู่ระบบผ่าน ONE ID ตรงเข้าสู่หน้า **Admin Dashboard (Step 11)**
     - สิทธิ์การใช้งานขึ้นอยู่กับการกำหนดของ Super Admin โดยเฉพาะสิทธิ์การส่งออกข้อมูล

2. **ระบบจัดการสิทธิ์ Admin (Admin Permission Management - Step 10)**:
   - เปิดให้เฉพาะผู้ใช้บทบาท `SUPER_ADMIN` เท่านั้นในการเข้าถึง (`/api/admin/users`)
   - รองรับฟังก์ชัน:
     - ดูรายชื่อผู้ดูแลระบบทั้งหมด พร้อมสถานะและสิทธิ์การใช้งาน
     - เพิ่มผู้ดูแลระบบใหม่ (ระบุบัญชี ONE ID, ชื่อ-นามสกุล, และสิทธิ์)
     - กำหนด/ปรับปรุงสิทธิ์ เช่น สิทธิ์การส่งออกข้อมูล (`can_export`)
     - ส่งออกรายชื่อผู้ดูแลระบบเป็นไฟล์รายงาน (Excel / CSV)
   - ทุกการเปลี่ยนแปลงสิทธิ์จะถูกบันทึก Audit Log ลงระบบอย่างถาวร 2 ปี

3. **การควบคุมการส่งออกข้อมูลและการซ่อนปุ่ม (Step 21 - Hide Export Button)**:
   - **Gating UI**: สำหรับ Admin ที่ไม่มีสิทธิ์ `can_export` ระบบจะต้อง **ซ่อนปุ่มส่งออกข้อมูล (Hide Export Button)** ออกจากหน้า Dashboard ทันทีตามข้อกำหนด Step 21
   - **Gating Server**: API Endpoint สำหรับ Export (`/api/admin/export/results`) บังคับใช้ Middleware ตรวจสอบสิทธิ์ `requirePermission('can_export')` หากผู้ใช้ไม่มีสิทธิ์ ระบบจะตอบกลับด้วย `403 Forbidden`

4. **การยืนยันรหัสผ่าน ONE ID ซ้ำ (Steps 13 & 22)**:
   - ทุกครั้งที่มีการขอส่งออกข้อมูล ผู้ใช้งานต้องระบุรหัสผ่านบัญชี ONE ID อีกครั้ง (Re-authentication)
   - หากรหัสผ่านไม่ถูกต้อง ระบบจะแจ้งเตือนว่า *"รหัสผ่านไม่ถูกต้อง ไม่สามารถดาวน์โหลดเอกสารได้"* (Step 23)
   - หากรหัสผ่านถูกต้อง ระบบจะประมวลผลไฟล์และบันทึก Audit Log โดยระบุผู้ส่งออก รูปแบบไฟล์ ตัวกรอง และเวลาส่งออก

## ผลตามมา

- การแบ่งแยกหน้าที่ (Separation of Duties) มีความชัดเจน สอดคล้องกับหลัก Least Privilege
- ป้องกันการเข้าถึงและนำข้อมูลสุขภาพของพนักงานออกนอกระบบโดยบุคลากรที่ไม่ได้รับอนุญาต
- มีหลักฐานการตรวจสอบสิทธิ์ (Audit Trail) ครอบคลุมทั้งการมอบสิทธิ์ การดูข้อมูล และการส่งออกข้อมูล
- รองรับการขยายตัวขององค์กรและการปรับเปลี่ยนโครงสร้างทีมงาน HR ได้อย่างยืดหยุ่น
