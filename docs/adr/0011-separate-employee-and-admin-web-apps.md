# ADR-0011: แยกเว็บพนักงานและเว็บ Admin

- สถานะ: ยอมรับแล้ว
- วันที่: 2026-09-02

## บริบท

ผู้ทำแบบประเมินและผู้ดูแลข้อมูลมีงาน สิทธิ์ และความเสี่ยงต่างกัน จึงต้องกำหนดว่าจะใช้หน้าเว็บเดียวตาม role หรือแยกเป็นคนละเว็บ

## การตัดสินใจ

ระบบมีเว็บสองส่วนแยกกัน:

1. **Employee Assessment Web** — สำหรับพนักงานทุกคนทำแบบประเมินและดูผลของตนเอง บุคลากร HR ก็ใช้เว็บนี้ในฐานะพนักงานได้
2. **Admin Web** — สำหรับ Admin ที่ได้รับสิทธิ์เท่านั้น ใช้ดูตารางผลรายบุคคล dashboard และดำเนินการรีเซ็ต

Admin Web ใช้บัญชีและรหัสผ่านที่สร้างเฉพาะในระบบนี้ ไม่ใช้ OnePlatform SSO

ไม่บังคับใช้ Multi-Factor Authentication (MFA) สำหรับ Admin

ระบบไม่มีหน้าจัดการบัญชี Admin นักพัฒนาที่ได้รับสิทธิ์เป็นผู้สร้าง ปิดใช้งาน และรีเซ็ตรหัสผ่านผ่านเครื่องมือหลังบ้านเท่านั้น

## ผลตามมา

- เว็บทั้งสองอาจ deploy คนละ hostname และมี navigation แยกจากกัน
- การแยกหน้าเว็บไม่ถือเป็นการควบคุมสิทธิ์ ทุก Admin API ต้องตรวจสิทธิ์ฝั่ง server
- บุคลากร HR ที่ไม่มีสิทธิ์ Admin ต้องไม่สามารถเข้า Admin API ได้
- ผู้ที่มีสิทธิ์ Admin ยังสามารถทำแบบประเมินของตนเองผ่าน Employee Assessment Web ได้
- รหัสผ่าน Admin ต้องเก็บด้วย password hashing ที่เหมาะสมและมี salt ห้ามเข้ารหัสแบบย้อนกลับหรือเก็บ plaintext
- ต้องจำกัดความถี่และจำนวนครั้งของการล็อกอินที่ล้มเหลว พร้อม audit log
- session/cookie ของ Admin ต้องแยกจาก Employee Assessment Web และตั้งค่า Secure, HttpOnly และ SameSite อย่างเหมาะสม
- เนื่องจากไม่มี MFA ต้องใช้มาตรการชดเชย ได้แก่ password policy ที่เน้นความยาว ตรวจรหัสผ่านที่ถูกเปิดเผย จำกัดความถี่ ล็อกชั่วคราวเมื่อผิดซ้ำ session อายุสั้น และแจ้งเตือนกิจกรรมเข้าสู่ระบบที่ผิดปกติ
- เครื่องมือหลังบ้านต้องเป็นคำสั่งหรือ workflow ที่ตรวจสอบได้ ไม่ใช้การแก้ไขฐานข้อมูลด้วยมือ
- การสร้าง ปิดใช้ และรีเซ็ตรหัสผ่านต้องมี audit trail ระบุผู้ดำเนินการ เวลา เป้าหมาย และประเภทการเปลี่ยนแปลง โดยไม่บันทึกรหัสผ่าน
- รหัสผ่านเริ่มต้นหรือ reset token ต้องมีอายุจำกัดและบังคับเปลี่ยนเมื่อเข้าสู่ระบบครั้งแรก
