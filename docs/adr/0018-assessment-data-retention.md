# ADR-0018: เก็บข้อมูลผลประเมิน 1 ปี และ Audit Log 2 ปี

- สถานะ: ยอมรับแล้ว
- วันที่: 2026-09-02 (ปรับปรุงตามข้อกำหนด 2026-09-07)

## บริบท

ผลประเมินและ employee snapshot เป็นข้อมูลส่วนบุคคลที่อ่อนไหว จึงไม่ควรเก็บโดยไม่มีกำหนด ขณะเดียวกันต้องเก็บบันทึก Audit Trail ไว้ตรวจสอบความโปร่งใสในระยะเวลาที่เหมาะสมตามเกณฑ์ PDPA และความมั่นคงปลอดภัย

## การตัดสินใจ

1. **อายุข้อมูลผลประเมิน (Assessment Data Retention)**: เก็บรอบประเมินทั้งสถานะ Submitted และ Cancelled ที่สามารถระบุตัวบุคคลได้เป็นเวลา **1 ปี** นับจากวันที่ส่งของแต่ละรอบ เมื่อครบ 1 ปี ระบบจะทำการ Anonymize ลบข้อมูลระบุตัวบุคคลและ employee snapshot ออก เหลือเฉพาะข้อมูลสถิติที่ไม่สามารถย้อนระบุตัวตนได้
2. **อายุบันทึกการใช้งาน (Audit Log Retention)**: บันทึก Audit Log เก็บรักษาอย่างปลอดภัยเป็นเวลา **2 ปี** ครอบคลุมการเข้าสู่ระบบ, การเปิดดู/ส่งออกข้อมูล (Export), การคืนสิทธิ์ (Reset), และกระบวนการทำงานทุกอย่าง (Event) ที่ผู้ดูแลระบบเข้าใช้งาน

## ผลตามมา

- ระบบต้องบันทึกวันส่งและวันที่ข้อมูลครบอายุ (1 ปี) อย่างชัดเจน
- หน้า Admin ควรแสดงหรือค้นหาวันครบอายุได้ตามความเหมาะสม
- มี scheduled retention job ที่ทำงานซ้ำได้อย่างปลอดภัยและบันทึก audit log
- กระบวนการ anonymize ต้องลบความสัมพันธ์ไปยังรหัสพนักงาน ชื่อ นามสกุล เพศ อายุ ข้อมูลติดต่อ และมิติที่ทำให้ระบุตัวได้
- หากการรวมมิติ เช่น บริษัทเล็ก ตำแหน่งเฉพาะ หรือพื้นที่ ทำให้กลุ่มเล็กเกินไป ต้องตัดมิตินั้นหรือรวมหมวดหมู่ก่อนเก็บ
- ข้อมูลที่ anonymize แล้วต้องไม่ปรากฏในการค้นหารายบุคคลหรือประวัติของพนักงาน
- อายุของ audit log กำหนดแยกจากอายุผลประเมิน โดยจัดเก็บเป็นเวลา 2 ปี
- บันทึก Audit Log ต้องบันทึกทุกกระบวนการทำงาน (Event) ของ Admin โดยห้ามบันทึกคำตอบรายข้อ, รหัสผ่าน, หรือ `shareToken` เด็ดขาด
- การเก็บ backup ต้องไม่ทำให้ข้อมูลที่ครบอายุกลับมาใช้งานตามปกติหลัง restore
