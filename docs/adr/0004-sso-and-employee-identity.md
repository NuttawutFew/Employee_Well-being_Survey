# ADR-0004: ยืนยันตัวตนด้วย SSO และเชื่อมข้อมูลพนักงาน

- สถานะ: ยอมรับแล้ว
- วันที่: 2026-09-02

## บริบท

ต้องกำหนดว่าการประเมินเป็นแบบไม่ระบุตัวตน หรือผูกกับตัวตนและประวัติของพนักงาน

## การตัดสินใจ

ผู้ใช้เข้าสู่ระบบด้วย Single Sign-On (SSO) จากนั้นระบบดึงข้อมูลพนักงานมาใช้และผูกการประเมินเข้ากับพนักงานคนนั้น

1. **ฝั่งพนักงาน (Employee)**: เข้าใช้งานผ่านทาง OnePlatform Application โดยใช้บัญชี OneID ของตนเอง ระบบจะทำการ Single-Sign-On (SSO) ให้อัตโนมัติ โดยระบบประเมินได้รับ `shareToken` และนำไปแลกข้อมูลโปรไฟล์พนักงาน เช่น ชื่อ นามสกุล เพศ อายุ บริษัท แผนก ตำแหน่ง และรหัสพนักงาน
2. **ฝั่งผู้ดูแลระบบ (Admin)**: เข้าหน้าเว็ประบบประเมินด้วยบัญชี OneID ของตนเอง และระบบทำการตรวจสอบการ map สิทธิ์เป็น Admin ในระบบเพื่ออนุญาตให้เข้าถึง Admin Web (ระบบการยืนยันตัวตนแบบ 2FA อยู่นอกขอบเขตระยะที่ 1)

OnePlatform/OneID ส่งรหัสพนักงานที่ไม่ซ้ำและคงที่มาด้วย ระบบใช้รหัสนี้เป็นตัวเชื่อมพนักงานกับประวัติการประเมิน ส่วนข้อมูลโปรไฟล์ใช้สำหรับแสดงผลและการบริหารจัดการ ไม่ใช้เป็นกุญแจอ้างอิง

## ผลตามมา

- ระบบต้องเชื่อถือรหัสพนักงานจาก identity provider ไม่รับค่าระบุตัวตนจากแบบฟอร์มฝั่งผู้ใช้
- สร้างส่วนเชื่อมต่อ OnePlatform เป็น adapter แยกจาก domain ของแบบประเมิน เพื่อรองรับการเปลี่ยน integration contract ภายหลัง
- ห้ามบันทึก `shareToken` ลง application log, analytics หรือฐานข้อมูลโดยไม่จำเป็น
- ต้องตรวจสอบ token และข้อมูลผู้ใช้ที่ฝั่ง server ก่อนสร้าง session ของระบบ
- ข้อมูลพนักงานที่ใช้ประกอบด้วยรหัสพนักงาน ชื่อ นามสกุล เพศ อายุ เบอร์โทร แผนก และตำแหน่ง โดยดึงจาก OnePlatform/OneID
- กำหนดสิทธิ์แบบแยกบทบาท (RBAC) และตรวจสอบสิทธิ์ทุก API
- ต้องมีนโยบายอายุข้อมูล การลบข้อมูล บันทึกการเข้าถึง และการปกป้องข้อมูลสุขภาพที่อ่อนไหว (เช่น PII Encryption และ UI Masking)
- ต้องสื่อให้พนักงานทราบอย่างโปร่งใสว่าผลถูกผูกกับตัวตนและใครเข้าถึงได้
